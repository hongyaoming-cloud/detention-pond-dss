## 第 18 章　完整設計流程：從不合格到可行解，以及讀懂「阻擋」

### 18.1 問題

第 14 章用手動試誤找到了幾個可行設計。本章改用模組 5 的受限設計篩選，讓軟體在宣告的範圍內自動搜尋。限制與第 10 章相同：Qallow = 0.080 m³/s、Hallow = 1.00 m、24 小時內殘留不超過 1 %。

### 18.2 準備：自由出流證據

受限篩選前必須完成自由出流證據。本範例是教學案例，所以勾選與紀錄都是教學假設。

1. 從基本案例開始（說明中心 → 工具書 → 按「回到基本案例」）。
2. 到模組 3，勾選「已確認自由出流邊界」與四項檢核。
3. 在「自由出流證據紀錄」填：教學假設（僅供練習）：單一出口自由出流，不受尾水、回水、淹沒或操作控制影響。
4. 在「篩選限制依據」填：教學假設（僅供練習）：Qallow 與 Hallow 為本書範例設定值。

實際工程中，這兩項紀錄要寫明圖說或檢查編號、檢核人與日期，以及限制值的法規來源。

### 18.3 範例一：最小滯洪量

1. 到模組 5，填 Qallow = 0.080、Hallow = 1.00，目標選「最小事件新增滯洪量 ΔSmax」，堰寬邊界保留 0.05 至 1.00 m。
2. 按「執行受限設計篩選」。

圖 18-1 是篩選結果。軟體在 60 至 600 m²（每 20 m² 一格）的面積與宣告的堰寬範圍內搜尋，再做 2 輪局部細化。

| 堰寬 b | 0.53 m（輸入欄顯示 0.525） |
| 事件新增滯洪量 ΔSmax | 92.0 m³ |
| 出流尖峰／容許值 | 0.0798 / 0.0800 m³/s |
| 最高水位／容許值 | 0.200 / 1.000 m |
| 排空殘留 | 0.07 / 1.00 % |

### 18.4 範例二：最小面積

把目標改成「最小平面面積 A」，再按一次「執行受限設計篩選」。

| 項目 | 結果 |
| --- | --- |
| 池面積 A | 100 m² |
| 堰寬 b | 0.05 m（停在宣告的下限） |
| 事件新增滯洪量 ΔSmax | 94.6 m³ |
| 出流尖峰／容許值 | 0.0782 / 0.0800 m³/s |
| 最高水位／容許值 | 0.946 / 1.000 m |

### 18.5 判讀兩個結果

- 兩個設計都符合所有限制，但取捨完全不同。最小滯洪量的設計水很淺（0.200 m），需要大面積；最小面積的設計只要 100 m²，但水深接近上限（0.946 m）。
- 最小面積的堰寬停在 0.05 m 的下限，畫面會提示「邊界案例」。這表示若允許更窄的堰，可能還能更小；但過窄的堰容易堵塞，下限應依維護需求決定，而不是為了更好的數字而放寬。
- 兩個結果都只是在宣告範圍內的條件式篩選，不是全域最佳解，也不是最終設計。

### 18.6 範例三：阻擋

把限制改得很嚴：Qallow = 0.040 m³/s、Hallow = 0.30 m，目標回到最小滯洪量，再按一次「執行受限設計篩選」。

結果顯示：「阻擋：在宣告的物理邊界與離散篩選範圍內找不到可行篩選案例。主導限制：出流尖峰限制、最高水位限制、排空殘留限制。」

這個阻擋是合理的：要把 0.120 m³/s 的尖峰壓到 0.040 m³/s，池子要存很多水；但水位又不能超過 0.30 m，面積上限 600 m² 也不夠。

正確的處理方式：

1. 先確認 Qallow 與 Hallow 的來源是否正確。若正確，就不可以為了得到解而放寬。
2. 依主導限制，考慮有工程依據的調整：例如土地允許時擴大面積範圍、改用其他出口型式，或分散成多個設施。
3. 若需要更大的面積，可以用連續最佳化設定較大的面積範圍再檢查。
