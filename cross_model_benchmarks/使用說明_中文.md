# HEC-HMS／SWMM 交叉驗算基準資料

本資料包以 A-005、B-005、C-005、D-005 四個實驗案例，涵蓋三角形與梯形入流，以及溢流堰與矩形孔口。目的為確認不同軟體對同一連續方程、蓄水關係與出流關係的數值結果是否一致；它不是現地實證驗證，也不是以 HEC-HMS 或 SWMM 取代本系統。

每一案例資料夾包含：

- `inflow_timeseries.csv`：原始實驗時間與入流，供追溯。
- `cross_model_inflow_timeseries.csv`：供 HEC-HMS 與 SWMM 匯入的時間尺度轉換入流。
- `hec_hms_elevation_storage.csv`：相對水位—增量蓄水量關係。
- `swmm_storage_curve.csv`：相對水位—水面積關係。
- `cross_model_outlet_rating.csv`：相對水位—增量出流量關係。
- `model_spec.json`：初始水位、尺度轉換與比較規格。

## 為何要進行時間尺度轉換

實驗歷線最小取樣間距為 0.25 秒，HEC-HMS 不宜以此秒級步長直接進行事件演算。因此設定一個實驗秒等於四個模型分鐘，也就是時間放大 240 倍。同時將入流與出流除以 240；水位與蓄水量維持不變。如此每個時間段的體積仍相同，連續方程完全守恆。

比較結果前，請將 HEC-HMS 或 SWMM 的出流乘以 240，並將模型時間（分鐘）除以 4，還原為實驗時間（秒）。

## HEC-HMS 設定

每案建立一個 Reservoir。初始蓄水量設為零；入流使用 `cross_model_inflow_timeseries.csv`；水位—蓄水量使用 `hec_hms_elevation_storage.csv`；水位—出流量使用 `cross_model_outlet_rating.csv`。計算與報表間距均設一分鐘。此一比對不得改用 HEC-HMS 內建的堰流或孔口係數公式，因為目的是檢核路由數值法，而不是檢核兩套軟體的係數定義差異。

## SWMM 設定

每案建立一個 Storage Unit，初始深度為零，不設定滲漏或入滲。蓄水曲線用 `swmm_storage_curve.csv`，直接外加入流用 `cross_model_inflow_timeseries.csv`，接至 Free Outfall 的 TABULAR outlet 使用 `cross_model_outlet_rating.csv`。流量單位設 CMS，路由與報表間距均設一分鐘。

## 通過門檻

還原尺度後，三套結果逐點比較；各案應同時滿足：尖峰出流差異不超過 0.5%、尖峰時間差不超過一個報表間距、最大蓄水量差異不超過 0.5%，且質量平衡殘差不超過 0.1%。未通過時須檢查時間尺度、初始水位、曲線內插方式與輸出間距，不能直接認定任何一套軟體錯誤。

## 成果自動比較

各案例的 `software_i_reference_output.csv` 是 Software I 的 RK4 基準結果。HEC-HMS 或 SWMM 匯出結果整理為模型時間（分鐘）、尺度化出流量、相對水位與蓄水量四欄後，執行：

`python3 compare_cross_model_outputs.py software_i_reference_output.csv 外部模型輸出.csv`

比較器會自動還原時間與流量尺度，輸出 RMSE、MAE、NSE、尖峰流量誤差、尖峰時間誤差、最高水位誤差與最大蓄水量誤差，並依既定門檻判定通過與否。`software_i_self_check_candidate.csv` 僅用來確認比較流程本身正常，不能當成 HEC-HMS 或 SWMM 的結果。
